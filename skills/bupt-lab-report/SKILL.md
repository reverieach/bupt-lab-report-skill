# 北邮课程实验报告

生成内容结构自适应、版式稳定的北邮课程报告。封面学生信息使用待填写占位符；生成正式报告前应从用户材料确认专业、班级、姓名和学号。

## 工作流

1. 读取用户本次要求以及所有可用材料。支持 DOCX、PDF、PPT/PPTX、表格、图片、代码、日志、项目文件和当前对话中明确可用的记忆。
2. 按以下优先级解决冲突：用户本次明确要求 > 教师模板或课程规范 > 用户提供的参考材料 > 本 skill 的北邮默认版式。
3. 提取可核实的任务、方法、过程、数据、结果和结论。不得虚构实验步骤、数值、截图、指标或成功结论；缺失内容使用清晰待补项或向用户确认。
4. 根据材料动态设计目录。只检查是否覆盖“目标、方法、过程、证据、分析、结论”等必要语义，不强制章节名称。
5. 读取 [内容适配规则](references/content-adaptation.md) 选择合适的章节组织；若用户提供目录，优先采用用户目录。
6. 读取 [版式规范](references/layout-spec.md)，保持北邮封面、标题、正文、图表、页码和目录样式。
7. 需要从结构化内容新建 DOCX 时，阅读 [生成规格](references/build-spec.md)，生成 JSON 后运行 `scripts/build_report.py`。需要修改教师模板时，优先在模板副本上编辑，不强制重建。
8. 运行 `scripts/validate_report.py` 检查关键版式和占位项。随后将 DOCX 渲染为逐页图片，检查每一页，修复裁切、重叠、孤立标题、图片过小、表格跨页或题注分离。
9. 输出最终 DOCX；用户要求时同时输出 PDF。提醒用户在 Word 中更新目录和域，除非已使用 Word/LibreOffice 更新并复核。

## 参考材料处理

- 从参考 DOCX/PDF/PPT 提取事实、术语、章节要求、图表和教师评分点；不要把幻灯片要点直接堆成正文。
- 从代码和日志提取环境、实现、参数、测试与真实输出；代码较长时正文只保留关键片段，其余放附录。
- 从图片读取标题、坐标轴、图例、单位和关键现象；无法辨认时不要猜测。
- 将记忆仅作为上下文线索；与本次材料冲突时以本次材料为准。
- 引用外部资料时保留来源信息；不要把参考材料中的个人信息误当成当前用户信息。

## 资源

- `assets/bupt-logo.png`：北邮蓝色透明校徽，封面默认使用。
- `assets/bupt-lab-report-template.docx`：不含个人信息的可编辑空白模板。
- `scripts/build_report.py`：从动态 JSON 结构生成 DOCX。
- `scripts/validate_report.py`：检查页面、样式、目录域、页码和占位项。

## 质量底线

- 不宣称该版式是北邮官方统一规范；表述为“根据课程报告样例整理的非官方模板”。
- 不因课程类型改变而强塞“实验原理、思考题、误差分析”等固定标题。
- 不把原始参考报告的通信原理内容复制到无关课程。
- 不把封面字段用连续空格对齐；使用表格、制表位或稳定布局。
- 封面必须完整位于第一页；学生信息值在固定下划线上居中，新增教师、日期等字段后也不得溢出。
- 中文标题必须显式使用黑体并写入 `zh-CN`，正文显式使用宋体；不得保留会触发 MS Gothic 的东亚主题字体属性。
- 保留图片原比例；图题置于图下、表题置于表上，编号在同一报告中一致。
- 正文、标题、表格与题注全部使用黑色字体，除非教师模板明确要求其他颜色。
