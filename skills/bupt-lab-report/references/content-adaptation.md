# 动态内容与章节适配

## 基本原则

先识别材料中真实发生的工作，再命名章节。章节名称是表达手段，不是检查清单。只要求报告在整体上交代目标、方法、过程、证据、分析与结论。

若用户提供教师目录、评分标准或模板，直接以其为骨架。若材料不足以支持某一章节，省略该章节或明确标记待补，不得填入通用套话冒充事实。

## 常见组织模式

以下只是候选结构，可以重排、合并、改名或删减。

### AI / 机器学习

- 任务定义与研究目标
- 数据集与预处理
- 环境、依赖与硬件配置
- 模型或方法设计
- 训练策略与超参数
- 评价指标与实验设置
- 结果、可视化与案例分析
- 基线、对比或消融实验
- 局限、失败案例与改进方向

不要在没有训练日志或结果时编造准确率、损失曲线或消融结论。

### 编程 / 软件工程

- 需求与功能目标
- 总体设计与模块划分
- 开发环境与依赖
- 数据结构、接口或核心流程
- 关键实现
- 测试方案、用例与运行结果
- 缺陷、调试过程与改进
- 总结

长代码放附录或仓库引用；正文解释关键设计与可验证结果。

### 算法 / 数据结构

- 问题定义与输入输出
- 算法思想或推导
- 正确性说明
- 复杂度分析
- 实现要点
- 测试数据与对比方案
- 结果分析与边界情况

### 物理 / 电路 / 硬件测量

- 实验目的
- 原理与仪器
- 电路、装置或测量方案
- 操作步骤
- 原始数据与处理
- 结果与误差分析
- 思考题（仅在指导书提供时）
- 结论

### 仿真 / 通信 / 控制

- 任务与指标
- 理论模型
- 仿真环境与参数
- 系统搭建或流程
- 波形、频谱或响应结果
- 参数对比与现象解释
- 结论与改进

### 综合课程设计 / 项目

- 背景与需求
- 约束和验收标准
- 总体方案
- 模块设计与实现
- 集成与验证
- 成果展示
- 风险、局限与后续工作

## 多实验报告

- 每个独立实验使用 Heading 1，实验内部使用 Heading 2/3。
- 相同的小节可以保持一致，也允许实验间结构不同。
- 跨实验的环境、公共方法或总体总结可以单独成章，避免重复。
- 图表编号按章重启；目录默认展示两级。

## 单次实验或短报告

- 不必人为创建“第一章”。可将主要逻辑部分作为 Heading 1。
- 小于约 5 页时谨慎使用三级标题。
- 目录是否保留服从教师要求；用户未指定时，正式课程报告默认保留。

## 信息缺失处理

- 缺少课程名称、题目等封面字段：询问用户或保留明显占位符。
- 缺少数据或运行结果：描述方法和预期记录项，不写成已完成结果。
- 缺少图像原文件：保留“待插入：图名”并列出所需图片。
- 多份材料冲突：指出冲突并采用优先级更高的来源。
